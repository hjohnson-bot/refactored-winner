# Hunter's Working Preferences

How Hunter wants work done. Every agent reads this before producing output for him.
Add entries only through the approval flow.

## Writing and delivery

- Direct answer first, supporting detail after. Never bury the bottom line.
- Emails and messages should sound like a person: direct, clear, not overly polished
  or robotic.
- Do not use em dashes in anything written for Hunter.
- Explain the why behind numbers, not just the variance amounts.
- Call out uncertainty plainly. Label anything unverified as unverified.
- Every major output ends with concrete next steps and named owners.

## Financial analysis

- Bridges must show actuals, forecast, budget, and job-level drivers.
- Separate timing changes from permanent changes in every variance explanation.
- Separate accounting issues (coding, timing, reclass) from true performance issues.
- Show period splits the way MDG plans: H1 actuals versus H2 forecast, then 2027
  and 2028 where relevant.
- State assumptions and a confidence level on every analysis.

## Deliverables

- Visually verify any rendered deliverable (map, dashboard, HTML, chart) before
  calling it done, including on mobile.
- No file is "final" until formulas, totals, and layout are checked.
- One primary owner per workstream. No two agents covering the same ground in a
  final answer.
